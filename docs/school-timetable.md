# 课表与活动往返

校园扩大后，旧版仍按每游戏分钟 4 个地图单位走路。从教室到学生活动中心，静态路线单程约 20 分钟；25 分钟课间又统一提前 10 分钟返课，无法容纳完整活动。

现在课程、课间、地图估时与自主返课共用 `school-tuning.json` 的 `clock`：

| 时间 | 安排 |
|---|---|
| 08:30–09:15 | 第一节课 |
| 09:15–10:00 | 自由活动 |
| 10:00–10:45 | 第二节课 |
| 10:45–11:30 | 自由活动 |
| 11:30–12:15 | 第三节课 |
| 12:15–13:45 | 午餐与午休 |
| 13:45–14:30 | 第四节课 |
| 14:30–18:30 | 放学后社团、运动与自由活动 |

这是为校园活动安排的游戏课表。走路速度为每游戏分钟 12 个地图单位，跨房间仍实际走过走廊与门口。游戏时间倍率保持不变。周一社团准备从早间改到 14:45，周四排练仍在 15:10；第一节课堂讨论于 08:44 开放，09:15 随课程结束。

## 行程预算

`clock.preparations` 声明角色应返回的物品位置与座位类型。通用时间模块使用执行器同一套障碍物与通行规则计算路线，再加 8 分钟离座、入座与门口让行余量。原来统一提前 10 分钟的中断条件已移除。

自动选择物理活动前，检查去程、活动时长、返程、让行余量与两个执行步骤是否都能在下节课前完成。不足时不把该活动交给自主决策；紧急身体需求仍可优先处理，玩家手动安排仍可执行。地图显示步行估时，课程面板显示距返课出发还有多少时间。进教室准备过程中即使响铃，也保留已有路线、位置与座位租约，继续进入课堂。

静态路线耗时按几何与通行权限缓存；地图或物品障碍变化会使缓存失效。人物碰撞仍由执行时的动态让行处理，不通过瞬移消除拥堵。

## 验证记录

`node scripts/observe-school-timing.mjs` 从原始 08:00 开局，用前端相同的半分钟步骤与两人普通决策预算运行。仅在第一节下课后安排玩家去活动中心下棋，不改人物位置、不跳时间、不指定 NPC 决策，之后放开自主返课。

本次 `research/timing/observation.json` 记录：

| 时间 | 实际行为 |
|---|---|
| 09:15:30 | 下课后出发 |
| 09:25 | 到达活动中心并开始下棋 |
| 09:30 | 完成活动，距上课还剩 30 分钟 |
| 09:59 | 回到教室座位 |
| 10:00 | 第二节课开始，继续听课 |

这次完整模拟没有迟到或缺课补做记录。耗时数据是本地进程的模拟与快照时间，测试同时运行，不能当作浏览器帧率。单条成功行程不保证任意拥堵、紧急需求或手动排队都能准时；预算是出发判断，世界中的实际阻挡仍然有效。

针对性回归检查完整往返预算、不同地点的返课时机、周末无强制返课、手动指令优先和铃响时保留行走路径；既有课程、午餐、情景、空间与内核回归检查原有行为。

## 旧存档

`timetableRevision` 增量更新课表与准备动作，不重置游戏时间、人物、记忆、关系、已有计划或手动指令。已发生的考勤保留为历史；新课表第一次接入时给 15 分钟过渡期，避免把更新前的时间追溯记成缺课，重新读档不会续期。进行中的行走改用新速度重新计算剩余路径。

内容生成入口为 `scripts/author-school-timetable.py`，在 `npm run author` 的最后执行，保证重新生成内容仍使用同一份课表。
