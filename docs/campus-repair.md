# 校园卡顿与行为连贯性修复

## 诊断依据

上一版校园 `situations` 为空；旧 `tickSituations` 仅按时写入私有通知。作息对每名 NPC 每天只生效一次，`study` 也允许图书馆书桌。因此 NPC 学八分钟后失去课堂安排，且可能把去图书馆当作上课。普通兴趣规则只反复选择一个活动，不能据此声称已有完整人格或生活规划。

正常速度的模拟位置每两秒返回一次。Canvas 另有 85ms 绘制上限，每次重画所有静态三角面。忙碌 NPC 仍重复进入候选计算和原生决策；没有活动的会话/日历也会克隆世界事务。

## 修复边界

- 位置快照约每 0.2 秒更新；认知频率独立限制，正在执行动作时只对实际邀请开放决策。
- 无会话/待过期约定时跳过空事务。原生目标的不可变描述可缓存，进度仍以 Soar SMem 为准；读档重新加载缓存。
- 静态几何按深度分层缓存，动态人物单独绘制，兼容模式目标约 30 帧。Canvas 仍采用近似画家排序。WebGL 默认关闭动态阴影并限制像素倍率。可见页面的动画回调被节流时使用计时器补绘；不在隐藏页面补跑。
- 学生有指定教室座位，课程可重复持续；老师在教室讲课。前端展示选中 NPC 的实际决策原因与未完成计划。
- 新增 `situations.js`，定义活动时窗、参与角色、状态、阶段、真实事件信号、角色任务提案与超时。内容仍来自 tuning。当前共用一个社团筹备模板，每周两次，尚不是两种不同剧情。
- `join-activity` / `skip-activity` 经 Soar 选择后才建立参与者计划。参加活动不等于同意具体分工；`project` proposal 仍需要真实会话与独立回答。
- 各阶段只安装角色可选择的任务知识；普通日程、需要和个人规则参与同一次操作仲裁。完成信号必须带本次情景 ID，不能把之前的同类行为当作完成。
- 原生记忆保存参与选择、同意/拒绝、阶段任务与进度。时窗结束使未完成目标失效；不伪造物品或动作完成。
- 公开 NPC 会话在镜头中展示台词，独立于玩家的个人见闻。当前台词是语义交互模板，不是实时自由生成对话。

## 验证

`npm test`：16/16 通过。其中四项新增回归针对本次问题：

1. 从课前开始连续模拟 85 分钟，检查上课切换与持续课堂，7 位 NPC 合计做 57 次行动决策；每人至少实际完成两段课程。
2. 无玩家命令时，参加、碰面、谈分工、同意、分别完成海报与音乐；周明远可以拒绝参与。
3. 在真实提案待回答时通过 PolicyInbox 安装另一条原生 Soar 规则，使沈乔拒绝，结果变为苏禾单独完成海报。
4. 画纸为零时无法假完成，中途原生存读档保持情景/目标；期限到后正常过期，没有重复目标。

这些测试证明机制与因果路径，不能等同于完整人格模型、长期有趣剧情或自由语义理解。没有调用外部付费模型 API。

已有存档包含旧 tuning 和旧规则，按原样恢复；新规则体验应重新开始一天。当前活动阶段任务由编写期内容提供，运行时规则接口可以改变选择；本次没有加入 AI 导演。

浏览器通过实际界面观察了参加/拒绝、完成筹备、玩家跨区移动和 09:04 全员课堂。选中人物显示实际规则原因。一次移动场景的 Canvas 样本为 21 fps、位置回写 184ms；这是测试浏览器的采样，不是所有设备的帧率保证。静态场景复用缓存时绘制计数可降为零。WebGL GPU 路径本轮未验收。证据见 `research/campus/repair-browser-evidence.json`。
