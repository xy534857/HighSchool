# 课堂 Situation 与个人自主性

每个工作日 08:44–09:15，教室开放一次练习讨论。原有听课、考勤、需要和个人计划继续运行。老师可以开启话题，在场同学可以尝试讲解、追问、支持、拿练习核对、承认准备不足或继续辩解；保持安静也是合法选择。

## 机制

| 层 | 职责 |
|---|---|
| Situation | 保存时间、地点、在场者和已经发生的公开事实；依据真实贡献推进阶段 |
| 候选生成 | 从个人可感知的场景绑定发言对象，检查阶段、准备程度和共享发言间隔 |
| 原生 Soar | 按本人的性格、已安装策略与其他优先事项选择；允许继续原来的活动 |
| 执行器 | 校验当前发言机会，在事务内记录贡献；不释放听课座位或重置课程进度 |
| 个人记忆与计划 | 只有现场观察者接收事件和评价关系；自己承诺补做才创建自己的课后目标 |
| 异步 LLM | 原有日终反思接收本人经历，可以调整以后的策略；课堂每轮无需网络推理 |

`members` 用内容条件匹配当时在场的人，没有固定主角名单。新课堂没有 `phases.plans`；阶段描述不能给角色安装发言脚本。`situation.contribute` 只改变 tuning 声明的共享字段，并串行占用每三游戏分钟一次的贡献机会。来自过期阶段、刚被别人占用的发言机会或已经离场对象的行动会被拒绝。

`during` 声明哪些瞬时贡献可以与正在执行的物理活动共存。只在该活动的 `perform` 阶段有效；行走、入座、离座和不可打断的活动不适用。角色的座位租约、剩余听课时间和考勤保持连续。表现层在原有坐姿上叠加发言手势。

Situation 不保证讨论解决问题。角色没有拿出依据，老师只能保留疑问；当众被追问的感受取决于观察者的性格。承认准备不足可以创建一个本人承诺的课后练习目标，必须实际完成 `study` 才算完成。辩解不会被自动改写成道歉或和解。

## 扩展与恢复

内容作者脚本为 `scripts/author-classroom-content.py`，已接入 `npm run author`。场景开放时间、阶段条件、发言候选和人物策略都在生成的 tuning 中。

旧存档通过 `classroomRevision` 增量安装内容和新增规则，保留原有人物、记忆、关系、个人计划和运行时规则。进行中的新课堂会保存发言者、问题、共享冷却和承诺；读取不会重新发放已完成的承诺。

专项回归在 `tests/campus/classroom.test.mjs`，覆盖全自动课堂、玩家发言与座位连续性、真实课后履约、不同回应的关系后果、观察范围、过期发言及新旧存档。完整的内核、校园和运行时回归共 49 项，全部通过。浏览器交互验收没有在本轮执行。
